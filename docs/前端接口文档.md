# 时迁前端接口文档

> 生成日期：2026-05-18  
> 前端项目：`shiqian-frontend`  
> 默认网关：`http://localhost:8080`  
> 前端请求前缀：`VITE_API_BASE_URL`，未配置时使用同源 `/api`

## 1. 通用约定

- 前端统一通过 `src/api/client.ts` 调用接口。
- 登录后将 `accessToken` 保存到 `localStorage.shiqian_access_token`。
- 所有登录态接口自动携带：

```http
Authorization: Bearer {accessToken}
Content-Type: application/json
```

- 后端统一返回：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

`code !== 200` 时前端抛出错误并在页面展示 `message`。

## 2. 用户与认证

### 2.1 注册

- 页面：`/register`
- 方法：`POST`
- 路径：`/api/user/register`
- 认证：否

请求体：

```json
{
  "username": "student01",
  "password": "123456",
  "nickname": "学生一号",
  "email": "student01@example.com",
  "phone": "13800138001"
}
```

前端行为：注册成功后立即调用登录接口。

### 2.2 登录

- 页面：`/login`
- 方法：`POST`
- 路径：`/api/user/login`
- 认证：否

请求体：

```json
{
  "username": "student01",
  "password": "123456"
}
```

响应 `data`：

```json
{
  "accessToken": "jwt",
  "refreshToken": "jwt",
  "userId": 2,
  "username": "student01",
  "nickname": "学生一号",
  "role": "USER"
}
```

前端行为：保存 Token；`ADMIN` 跳转后台首页，`USER` 跳转用户首页。

### 2.3 获取当前用户

- 使用方：页面初始化、登录态恢复
- 方法：`GET`
- 路径：`/api/user/me`
- 认证：是

响应 `data`：

```json
{
  "userId": 2,
  "username": "student01",
  "nickname": "学生一号",
  "email": "student01@example.com",
  "phone": "13800138001",
  "avatar": "",
  "role": "USER",
  "status": 1,
  "createTime": "2026-05-18T10:00:00"
}
```

### 2.4 管理员用户分页

- 页面：`/user-admin`
- 方法：`GET`
- 路径：`/api/user/admin/users`
- 认证：是
- 权限：`user:manage`
- 参数：`page`、`size`、`keyword`

响应：`Page<UserInfoVO>`。

## 3. 分类

### 3.1 获取分类树

- 页面：首页、分类浏览、发布资源、分类管理
- 方法：`GET`
- 路径：`/api/category/tree`
- 认证：否

响应：`Category[]`，支持 `children` 递归。

### 3.2 新增分类

- 页面：`/category-admin`
- 方法：`POST`
- 路径：`/api/category`
- 认证：后端当前未强制，前端仅在后台入口调用

请求体：

```json
{
  "name": "课程笔记",
  "parentId": 0,
  "sortOrder": 1,
  "status": 1
}
```

### 3.3 更新分类

- 页面：`/category-admin`
- 方法：`PUT`
- 路径：`/api/category/{id}`

请求体同新增分类。

### 3.4 删除分类

- 预留接口
- 方法：`DELETE`
- 路径：`/api/category/{id}`

## 4. 资源

### 4.1 资源列表

- 页面：首页、资源广场、后台资源管理、审核页
- 方法：`GET`
- 路径：`/api/resource`
- 认证：否
- 参数：`page`、`size`、`categoryId`、`keyword`

响应：`Page<Resource>`。

前端说明：
- 用户广场只展示 `status=1` 的资源。
- 后台展示所有状态。
- `categoryId` 由分类树中的 `id` 转换而来。

### 4.2 资源详情

- 页面：`/detail/:id`
- 方法：`GET`
- 路径：`/api/resource/{id}`
- 认证：否

前端打开详情时，如已登录会额外请求收藏状态。

### 4.3 发布资源

- 页面：`/publish`
- 方法：`POST`
- 路径：`/api/resource`
- 认证：是
- 权限：`resource:create`

请求体：

```json
{
  "title": "数据结构复习笔记",
  "description": "包含重点题型与真题解析",
  "categoryId": 1,
  "fileUrl": "https://example.com/demo.pdf",
  "fileSize": 102400,
  "fileType": "pdf"
}
```

前端说明：
- 发布页先调用附件上传接口拿到真实 `fileUrl`。
- 单个附件创建 1 条资源。
- 多个附件会批量创建多条待审核资源，标题规则为 `{资源标题} - {原始文件名}`。

### 4.4 批量上传附件

- 页面：`/publish`
- 方法：`POST`
- 路径：`/api/resource/files`
- 认证：是
- 权限：`resource:create`
- Content-Type：`multipart/form-data`
- 表单字段：`files`，支持多个文件

响应 `data`：

```json
[
  {
    "originalName": "network-lab.pdf",
    "fileUrl": "/api/resource/files/uuid.pdf",
    "fileSize": 2456789,
    "fileType": "application/pdf"
  }
]
```

### 4.5 访问附件

- 方法：`GET`
- 路径：`/api/resource/files/{filename}`
- 认证：否

用于详情页下载时打开真实附件地址。

### 4.6 我的发布

- 页面：`/mine`
- 方法：`GET`
- 路径：`/api/resource/mine`
- 认证：是
- 权限：`resource:read`
- 参数：`page`、`size`

响应：当前用户上传的 `Page<Resource>`。

### 4.7 删除我的资源

- 页面：`/mine`
- 方法：`DELETE`
- 路径：`/api/resource/{id}`
- 认证：是
- 权限：`resource:delete`

后端只允许上传者本人删除。

### 4.8 下载资源

- 页面：`/detail/:id`
- 方法：`POST`
- 路径：`/api/resource/{id}/download`
- 认证：否

前端行为：请求成功后下载数本地 +1；如资源存在 `fileUrl`，打开新窗口。

### 4.9 收藏/取消收藏

- 页面：资源卡片、资源详情
- 收藏：`POST /api/resource/{id}/favorite`
- 取消：`DELETE /api/resource/{id}/favorite`
- 查询状态：`GET /api/resource/{id}/favorite`
- 认证：是

### 4.10 我的收藏

- 页面：`/favorites`
- 方法：`GET`
- 路径：`/api/resource/favorites`
- 认证：是
- 权限：`resource:favorite`
- 参数：`page`、`size`

响应：当前用户收藏资源的 `Page<Resource>`。

### 4.11 搜索资源

- 页面：首页搜索框、资源广场
- 方法：`GET`
- 路径：`/api/resource/search`
- 认证：否
- 参数：`keyword`、`page`、`size`

响应：`Page<ResourceDocument>`，前端拿到搜索 ID 后会再请求详情接口补齐下载数、文件地址等字段。

搜索说明：
- 后端使用 Elasticsearch。
- 搜索字段覆盖 `title`、`description`、`fileType`。
- 后端查询包含 `multi_match`、`match_phrase`、`wildcard` 和英文/数字 `fuzziness=AUTO`，避免只在完全命中时才返回。
- 前端普通用户仍只展示 `status=1` 的已发布结果。

### 4.12 审核资源

- 页面：`/audit`、`/admin`
- 方法：`PUT`
- 路径：`/api/resource/{id}/audit`
- 认证：是
- 权限：`resource:audit`
- 参数：`status=1` 通过，`status=2` 驳回

## 5. 前端数据映射

资源状态：

| 后端 status | 前端文案 |
|---|---|
| 0 | 待审核 |
| 1 | 已发布 |
| 2 | 已驳回 |

用户角色：

| 后端 role | 前端角色 |
|---|---|
| USER | student |
| ADMIN | admin |

资源字段：

| 后端字段 | 前端字段 |
|---|---|
| `title` | `title` |
| `description` | `desc` |
| `categoryId` | `categoryId` + 分类名 `cat` |
| `fileType` | `type` |
| `userId` | `author` 临时显示为 `用户 {userId}` |
| `downloadCount` | `downloads` |
| `status` | `status` 文案 |
