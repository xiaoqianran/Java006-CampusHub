## 1. 整体架构

前端**不直接散落** `fetch/axios` 调用，所有接口访问均通过 **单一数据源**：

```
视图 (Vue SFC) 
   ↓ 调用 actions
Pinia Store (stores/app.ts)  ← 唯一 API Facade
   ↓ 统一 request()
src/api/client.ts (薄封装 fetch + Token + Result 规范化)
   ↓ HTTP
Gateway 8080 → 后端微服务
```

**优势**：
- 集中管理请求、错误、loading、乐观更新、数据合并
- 便于 mock、权限拦截、全局 loading
- 所有 TypeScript 类型定义集中

## 2. 通用请求封装（client.ts）

### 2.1 核心类型

```ts
export interface Result<T> {
  code: number
  message: string
  data: T
}

export interface PageResult<T> {
  records: T[]
  total: number
  size: number
  current: number
  pages: number
}
```

### 2.2 认证与 Header 规则

- `localStorage.shiqian_access_token` 持久化
- 自动注入：`Authorization: Bearer {token}`
- `Content-Type: application/json`（除 FormData）
- 统一错误处理：`code !== 200` 抛出 `Error(message)`

### 2.3 关键函数

| 函数 | 用途 |
|------|------|
| `request<T>(path, options)` | 核心封装，支持 `query`、`method`、`body` |
| `jsonBody(payload)` | JSON.stringify 快捷 |
| `setTokens / clearTokens / getAccessToken` | Token 管理 |
| `buildUrl` | 支持相对/绝对 base + query 序列化 |

**Vite 代理**（开发环境）：
```ts
// vite.config.ts
proxy: { '/api': { target: 'http://localhost:8080', changeOrigin: true } }
```

## 4. 完整 API 方法表（Store Actions → 后端接口）

| Store Action | HTTP | 路径 | 认证 | 权限 | 说明与前端副作用 |
|--------------|------|------|------|------|------------------|
| `login` | POST | `/api/user/login` | 否 | - | 存 Token + role + 拉取收藏/我的资源 |
| `register` | POST | `/api/user/register` | 否 | - | 成功后自动调用 login |
| `loadCurrentUser` | GET | `/api/user/me` | 是 | - | 恢复登录态、同步 currentUser |
| `loadUsers` | GET | `/api/user/admin/users` | 是 | user:manage | 后台用户管理 |
| `loadCategories` | GET | `/api/category/tree` | 否 | - | 填充 categoryTree + flatCategories |
| `createCategory` / `updateCategory` / `deleteCategory` | POST/PUT/DELETE | `/api/category...` | 是 | - | 后台分类管理，操作后自动 reload |
| `loadResources` | GET | `/api/resource` | 否 | - | 支持 categoryId/keyword 分页，mergeResources |
| `searchResources` | GET | `/api/resource/search` | 否 | - | ES 搜索，设置 searchResultIds，后补详情 |
| `loadResourceDetail` | GET | `/api/resource/{id}` | 否 | - | 详情 + 已登录时查收藏状态 |
| `loadFavorites` | GET | `/api/resource/favorites` | 是 | resource:favorite | 我的收藏 + 填充 favoriteIds |
| `loadMyResources` | GET | `/api/resource/mine` | 是 | resource:read | 我的发布 |
| `submitResource` | POST | `/api/resource` | 是 | resource:create | 支持 attachments 数组 + Markdown |
| `uploadFiles` | POST | `/api/resource/files` | 是 | resource:create | FormData，多文件上传，返回 UploadedFileItem[] |
| `toggleFavorite` | POST/DELETE | `/api/resource/{id}/favorite` | 是 | - | 乐观更新 favoriteIds |
| `refreshFavoriteState` | GET | `/api/resource/{id}/favorite` | 是 | - | 详情页同步收藏状态 |
| `downloadResource` | POST | `/api/resource/{id}/download` | 否 | - | 乐观 +1 downloads |
| `removeMyResource` | DELETE | `/api/resource/{id}` | 是 | resource:delete | 仅本人可删，UI 立即移除 |
| `approveResource` / `rejectResource` | PUT | `/api/resource/{id}/audit?status=1/2` | 是 | resource:audit | 后台审核，乐观更新 status |

## 5. 关键业务流程实现

### 5.1 富内容发布流程（2026-05 新特性）

1. PublishView 表单：`title + cat + summary + contentMarkdown`
2. 可选附件：`uploadFiles(files)` → 拿到 `fileUrl` 列表
3. `submitResource(payload)` 内部构造：
   ```json
   {
     "title": "...",
     "categoryId": 12,
     "summary": "...",
     "contentMarkdown": "# 正文...",
     "contentType": "MARKDOWN",
     "attachments": [ {fileName, fileUrl, ...} ]
   }
   ```
4. 后端创建资源 + 附件记录 + ES 同步

**注意**：当前后端仍支持旧 `description` + `fileUrl` 兼容，但前端主推新字段。

### 5.2 搜索 + 补全策略

- 先调用 `/search`（轻量 ES 结果）
- 再对每个结果调用 `loadResourceDetail(id)` 补全 `downloadCount`、`fileUrl` 等
- 最终合并到 `resources` 响应式数组

### 5.3 乐观更新示例

- `downloadResource`：立即 `item.downloads += 1`
- `toggleFavorite`：立即修改 `favoriteIds`
- `approve/reject/remove`：立即改状态或过滤列表

## 6. 各页面 / 视图的 API 依赖矩阵

| 页面 (路由) | 主要调用的 Store 方法 | 说明 |
|-------------|-----------------------|------|
| `/` HomeView + PlazaView | `loadHomeData`, `searchResources`, `setCategory` | 首页加载分类+资源，搜索触发 ES |
| `/detail/:id` | `loadResourceDetail`, `toggleFavorite`, `downloadResource` | 详情 + 收藏 + 下载 |
| `/publish` | `loadCategories`, `uploadFiles`, `submitResource` | 富文本 + 附件发布 |
| `/mine` | `loadMyResources`, `removeMyResource` | 我的资源管理 |
| `/favorites` | `loadFavorites` | 收藏列表 |
| `/login` `/register` | `login`, `register` | 认证入口，成功跳首页或后台 |
| `/admin/*` (AuditView, ResourceAdminView, CategoryAdminView, UserAdminView) | `loadUsers`, `approveResource`, `rejectResource`, `create/update/deleteCategory`, `loadResources` | 仅 ADMIN 可见，权限由后端 403 兜底 |

**权限控制**：
- 前端用 `store.role` + `store.logged` 控制菜单/按钮显示
- 关键操作仍依赖后端 `@PreAuthorize` 返回 403，store 统一抛错 → Element Plus Message 提示

## 8. 错误与边界处理

- 所有 `request` 失败均抛 `Error`，上层 `.catch()` 后 `ElMessage.error`
- 未登录操作收藏/发布 → 引导登录
- 分类不存在提交 → 前端提前 `throw`
- 搜索空关键词 → 退化普通列表加载

---

## 9. 开发与部署注意事项

1. **环境变量**：`VITE_API_BASE_URL` 可覆盖（生产可指向正式网关）
2. **Token 刷新**：当前未实现 `refreshToken` 自动续期（后端已签发 7d refreshToken，预留接口）
3. **附件访问**：返回的 `fileUrl` 是 `/api/resource/files/xxx`，走网关公开访问
4. **Markdown 渲染**：使用 `md-editor-v3` + 自定义 `MarkdownPreview` 组件
5. **构建**：`npm run build` 后 `dist/` 可直接被 gateway 静态托管（已有 `shiqian-frontend/dist`）

## 10. 现状评估与建议（2026-05-18 23:00）

**已完成优秀实践**：
- 单一数据源 + 类型安全
- 完整支持后端新 Markdown + Attachments 模型
- 乐观更新 + 数据合并策略良好

**待改进点**（与后端测试报告一致）：
- 建议增加 `refreshToken` 自动续期机制
- 文件上传 multipart 在某些浏览器/大文件场景可增加进度 + 分片
- 后端 `updateResource` 目前缺少 owner 校验（前端已限制仅本人入口，但建议后端加固）
- 推荐引入 `vue-query` / `pinia-plugin-persistedstate` 进一步简化 loading/cache
