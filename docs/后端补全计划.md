## 2. 数据库 SQL 建议

当前表结构已能支撑本次新增接口，无需新增表。建议补充索引和唯一约束，便于分页查询与模拟数据稳定执行：

```sql
USE shiqian_user;

ALTER TABLE t_user
  ADD UNIQUE KEY uk_email (email),
  ADD UNIQUE KEY uk_phone (phone);

USE shiqian_resource;

ALTER TABLE t_resource
  ADD INDEX idx_user_deleted_create (user_id, deleted, create_time),
  ADD INDEX idx_status_deleted_create (status, deleted, create_time);

ALTER TABLE t_category
  ADD UNIQUE KEY uk_parent_name (parent_id, name);
```

如果目标库已经存在这些索引，请跳过重复执行。

## 4. 后续接口建议

1. 文件存储：当前已支持本地磁盘批量上传，生产环境建议替换为 MinIO/OSS 签名直传。
2. 资源列表过滤：`GET /api/resource` 建议增加 `status` 参数，默认只返回已发布，后台传 `status` 或 `includeAll=true`。
3. 用户管理操作：补禁用/启用用户接口，例如 `PUT /api/user/admin/users/{id}/status`。
4. 资源作者信息：资源列表建议返回 `nickname` 或提供批量用户查询，前端目前只能显示 `用户 {userId}`。
5. 审核日志：补审核记录表和查询接口，支撑后台审计。
6. 刷新 Token：补 `POST /api/user/refresh`，前端已有 `refreshToken` 存储位置。
7. ES 中文分词：当前使用 standard analyzer + wildcard 容错，生产环境建议切换 IK 分词并重建索引。
